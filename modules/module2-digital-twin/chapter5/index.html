Chapter 5: Gazebo Environment Setup

Learning Objectives​

By the end of this chapter, you will be able to:

  1. Understand the structure and syntax of URDF and SDF file formats
  2. Create and configure Gazebo world files with custom environments
  3. Convert between URDF and SDF formats for robot models
  4. Spawn robots and objects into Gazebo simulations programmatically
  5. Design realistic environments with proper physics, lighting, and terrain
  6. Integrate Gazebo with ROS 2 for robot control and sensing
  7. Debug common issues in Gazebo simulations

5.1 Introduction to Gazebo​

Gazebo is an open-source 3D robotics simulator that provides:

  • High-fidelity physics simulation
  • Sensor simulation (cameras, LiDAR, IMU, etc.)
  • Realistic rendering with lighting and shadows
  • Integration with ROS 2 through ros_gz bridge
  • Plugin architecture for custom functionality

Gazebo vs. Other Simulators​

Open SourceYesNoPartial
Physics EnginesODE, Bullet, DART, SimbodyPhysXPhysX
ROS 2 IntegrationNative (ros_gz)ROS 2 bridgeROS TCP/UDP

Gazebo Evolution

Gazebo has undergone significant evolution. Gazebo Classic (versions 1-11) is being replaced by Gazebo Sim (formerly Ignition Gazebo), which offers improved architecture, better performance, and modern rendering. This chapter focuses on Gazebo Sim (Harmonic release), which is the recommended version for ROS 2 Humble and beyond.

5.2 URDF: Unified Robot Description Format​

URDF (Unified Robot Description Format) is an XML-based format for describing robot structures in ROS.

5.2.1 URDF Structure​

A URDF file consists of links (rigid bodies) and joints (connections between links).

Minimal URDF Example:

<?xml version="1.0"?>
<robot name="simple_robot">
  <!-- Base link (required root link) -->
  <link name="base_link">
    <visual>
      <geometry>
        <box size="0.5 0.3 0.2"/>
      </geometry>
      <material name="blue">
        <color rgba="0 0 1 1"/>
      </material>
    </visual>
    <collision>
      <geometry>
        <box size="0.5 0.3 0.2"/>
      </geometry>
    </collision>
    <inertial>
      <mass value="10.0"/>
      <inertia ixx="0.1" ixy="0.0" ixz="0.0"
               iyy="0.2" iyz="0.0" izz="0.15"/>
    </inertial>
  </link>

  <!-- Wheel link -->
  <link name="wheel">
    <visual>
      <geometry>
        <cylinder radius="0.1" length="0.05"/>
      </geometry>
      <material name="black">
        <color rgba="0 0 0 1"/>
      </material>
    </visual>
    <collision>
      <geometry>
        <cylinder radius="0.1" length="0.05"/>
      </geometry>
    </collision>
    <inertial>
      <mass value="1.0"/>
      <inertia ixx="0.01" ixy="0.0" ixz="0.0"
               iyy="0.01" iyz="0.0" izz="0.005"/>
    </inertial>
  </link>

  <!-- Joint connecting base to wheel -->
  <joint name="wheel_joint" type="continuous">
    <parent link="base_link"/>
    <child link="wheel"/>
    <origin xyz="0.2 0 -0.1" rpy="0 1.57 0"/>
    <axis xyz="0 0 1"/>
  </joint>
</robot>

5.2.2 Link Elements​

Each <link> contains three main components:

1. Visual (appearance):

<visual>
  <origin xyz="0 0 0" rpy="0 0 0"/>
  <geometry>
    <mesh filename="package://robot_description/meshes/torso.dae"/>
    <!-- OR primitives: box, cylinder, sphere -->
  </geometry>
  <material name="grey">
    <color rgba="0.5 0.5 0.5 1.0"/>
  </material>
</visual>

2. Collision (physics):

<collision>
  <origin xyz="0 0 0" rpy="0 0 0"/>
  <geometry>
    <box size="0.4 0.3 0.6"/>  <!-- Simplified for performance -->
  </geometry>
</collision>

3. Inertial (dynamics):

<inertial>
  <mass value="15.0"/>  <!-- kg -->
  <origin xyz="0 0 0.3" rpy="0 0 0"/>  <!-- Center of mass -->
  <inertia ixx="0.3" ixy="0.0" ixz="0.0"
           iyy="0.25" iyz="0.0" izz="0.1"/>
</inertial>
Inertia Calculation

For simple shapes, inertia tensors can be calculated analytically:

  • Box: Ixx = (1/12) * m * (h² + d²)
  • Cylinder: Izz = (1/2) * m * r²
  • Sphere: I = (2/5) * m * r²

For complex meshes, use CAD software (SolidWorks, Fusion 360) to compute inertial properties automatically.

5.2.3 Joint Types​

Joint Types in URDF:

  1. Fixed: No motion (e.g., sensors attached to robot body)

    <joint name="camera_joint" type="fixed">
      <parent link="head"/>
      <child link="camera"/>
      <origin xyz="0.1 0 0.05" rpy="0 0 0"/>
    </joint>

  2. Revolute: Rotational motion with limits

    <joint name="elbow_joint" type="revolute">
      <parent link="upper_arm"/>
      <child link="forearm"/>
      <origin xyz="0 0 0.3" rpy="0 0 0"/>
      <axis xyz="0 1 0"/>  <!-- Rotation axis -->
      <limit lower="-2.0" upper="2.0" effort="50" velocity="2.0"/>
    </joint>

  3. Continuous: Unlimited rotation (e.g., wheels)

    <joint name="wheel_joint" type="continuous">
      <axis xyz="0 1 0"/>
      <limit effort="10" velocity="5.0"/>
    </joint>

  4. Prismatic: Linear sliding motion

    <joint name="lift_joint" type="prismatic">
      <axis xyz="0 0 1"/>
      <limit lower="0.0" upper="0.5" effort="100" velocity="0.5"/>
    </joint>

5.3 SDF: Simulation Description Format​

SDF (Simulation Description Format) is Gazebo's native format. It's more expressive than URDF and supports:

  • Multiple robots in one file
  • Nested models
  • Plugins for sensors and controllers
  • World descriptions (lighting, terrain, physics)

5.3.1 SDF vs URDF​

FeatureURDFSDF
Multiple robotsNoYes
PluginsLimitedExtensive
World descriptionNoYes
ComplexitySimpleMore flexible
ROS compatibilityNativeVia conversion

5.3.2 SDF Model Structure​

      </inertial>

          <cylinder>
            <radius>0.1</radius>

5.4 Converting Between URDF and SDF​

5.4.1 URDF to SDF Conversion​

Gazebo automatically converts URDF to SDF when loading. You can also manually convert:

Using gz command-line tool:

# Convert URDF to SDF
gz sdf -p robot.urdf > robot.sdf

# Validate SDF file
gz sdf --check robot.sdf

Programmatic Conversion in Python:

import subprocess

def urdf_to_sdf(urdf_path, sdf_path):
    """Convert URDF file to SDF format."""
    try:
        result = subprocess.run(
            ['gz', 'sdf', '-p', urdf_path],
            capture_output=True,
            text=True,
            check=True
        )
        with open(sdf_path, 'w') as f:
            f.write(result.stdout)
        print(f"Converted {urdf_path} to {sdf_path}")
    except subprocess.CalledProcessError as e:
        print(f"Conversion failed: {e.stderr}")

# Usage
urdf_to_sdf('humanoid.urdf', 'humanoid.sdf')

5.4.2 Key Differences During Conversion​

URDF Feature → SDF Equivalent:

  1. Materials: URDF <color> → SDF <material><ambient> and <diffuse>
  2. Transmission: Not directly supported in SDF (use plugins)
  3. Gazebo tags: URDF <gazebo> tags are processed during conversion
  4. Plugins: Must be added to SDF explicitly

5.5 Gazebo World Files​

A world file defines the complete simulation environment: terrain, lighting, physics, and models.

5.5.1 Basic World Structure​

<?xml version="1.0"?>
<sdf version="1.9">
  <world name="humanoid_world">
    <!-- Physics configuration -->
    <physics name="1ms" type="ode">
      <max_step_size>0.001</max_step_size>
      <real_time_factor>1.0</real_time_factor>
      <real_time_update_rate>1000</real_time_update_rate>
    </physics>

    <!-- Gravity -->
    <gravity>0 0 -9.81</gravity>

    <!-- Magnetic field (for compass sensors) -->
    <magnetic_field>6e-6 2.3e-5 -4.2e-5</magnetic_field>

    <!-- Atmosphere (for drag calculations) -->
    <atmosphere type="adiabatic"/>

    <!-- Scene settings -->
    <scene>
      <ambient>0.4 0.4 0.4 1</ambient>
      <background>0.7 0.7 0.7 1</background>
      <shadows>true</shadows>
      <grid>false</grid>
    </scene>

    <!-- Sun (directional light) -->
    <light type="directional" name="sun">
      <cast_shadows>true</cast_shadows>
      <pose>0 0 10 0 0 0</pose>
      <diffuse>0.8 0.8 0.8 1</diffuse>
      <specular>0.2 0.2 0.2 1</specular>
      <attenuation>
        <range>1000</range>
        <constant>0.9</constant>
        <linear>0.01</linear>
        <quadratic>0.001</quadratic>
      </attenuation>
      <direction>-0.5 0.1 -0.9</direction>
    </light>

    <!-- Ground plane -->
    <model name="ground_plane">
      <static>true</static>
      <link name="link">
        <collision name="collision">
          <geometry>
            <plane>
              <normal>0 0 1</normal>
              <size>100 100</size>
            </plane>
          </geometry>
          <surface>
            <friction>
              <ode>
                <mu>1.0</mu>
                <mu2>1.0</mu2>
              </ode>
            </friction>
          </surface>
        </collision>
        <visual name="visual">
          <geometry>
            <plane>
              <normal>0 0 1</normal>
              <size>100 100</size>
            </plane>
          </geometry>
          <material>
            <ambient>0.8 0.8 0.8 1</ambient>
            <diffuse>0.8 0.8 0.8 1</diffuse>
          </material>
        </visual>
      </link>
    </model>
  </world>
</sdf>

Lighting for Vision Tasks

For computer vision tasks (object detection, SLAM), proper lighting is critical:

  • Use ambient light for minimum visibility: 0.4-0.6
  • Add directional light for shadows and depth perception
  • Point lights for indoor scenes
  • Avoid over-saturated lighting (diffuse > 0.9) which washes out details

Generating Heightmap in Python:

import numpy as np
from PIL import Image

def generate_terrain_heightmap(width=256, height=256, scale=10.0):
    """Generate random terrain heightmap."""
    # Create Perlin-like noise (simplified)
    x = np.linspace(0, scale, width)
    y = np.linspace(0, scale, height)
    X, Y = np.meshgrid(x, y)

    # Combine multiple sine waves for terrain variation
    Z = (np.sin(X) + np.sin(Y) +
         0.5 * np.sin(2*X) + 0.5 * np.sin(2*Y) +
         0.25 * np.sin(4*X) + 0.25 * np.sin(4*Y))

    # Normalize to 0-255
    Z = ((Z - Z.min()) / (Z.max() - Z.min()) * 255).astype(np.uint8)

    # Save as grayscale image
    img = Image.fromarray(Z, mode='L')
    img.save('terrain_heightmap.png')
    print("Heightmap saved to terrain_heightmap.png")

generate_terrain_heightmap()

5.7 Spawning Robots in Gazebo​

5.7.1 Spawning via Launch Files​

ROS 2 Launch File with Gazebo:

# spawn_humanoid.launch.py
import os
from launch import LaunchDescription
from launch.actions import IncludeLaunchDescription, ExecuteProcess
from launch.launch_description_sources import PythonLaunchDescriptionSource
from launch_ros.actions import Node
from ament_index_python.packages import get_package_share_directory

def generate_launch_description():
    # Paths
    pkg_gazebo_ros = get_package_share_directory('gazebo_ros')
    pkg_robot_description = get_package_share_directory('humanoid_description')

    world_file = os.path.join(pkg_robot_description, 'worlds', 'humanoid_world.sdf')
    urdf_file = os.path.join(pkg_robot_description, 'urdf', 'humanoid.urdf')

    # Read URDF
    with open(urdf_file, 'r') as f:
        robot_desc = f.read()

    # Gazebo server (simulation)
    gzserver = IncludeLaunchDescription(
        PythonLaunchDescriptionSource(
            os.path.join(pkg_gazebo_ros, 'launch', 'gzserver.launch.py')
        ),
        launch_arguments={'world': world_file}.items()
    )

    # Gazebo client (GUI)
    gzclient = IncludeLaunchDescription(
        PythonLaunchDescriptionSource(
            os.path.join(pkg_gazebo_ros, 'launch', 'gzclient.launch.py')
        )
    )

    # Spawn robot
    spawn_entity = Node(
        package='gazebo_ros',
        executable='spawn_entity.py',
        arguments=[
            '-entity', 'humanoid',
            '-topic', 'robot_description',
            '-x', '0',
            '-y', '0',
            '-z', '0.5'
        ],
        output='screen'
    )

    # Robot state publisher
    robot_state_publisher = Node(
        package='robot_state_publisher',
        executable='robot_state_publisher',
        output='screen',
        parameters=[{'robot_description': robot_desc}]
    )

    return LaunchDescription([
        gzserver,
        gzclient,
        robot_state_publisher,
        spawn_entity
    ])

5.7.2 Spawning Programmatically​

Python Node to Spawn Robot:

import rclpy
from rclpy.node import Node
from gazebo_msgs.srv import SpawnEntity
import os

class RobotSpawner(Node):
    def __init__(self):
        super().__init__('robot_spawner')

        # Create service client
        self.spawn_client = self.create_client(SpawnEntity, '/spawn_entity')

        while not self.spawn_client.wait_for_service(timeout_sec=5.0):
            self.get_logger().info('Waiting for /spawn_entity service...')

        self.get_logger().info('Spawn service is ready!')

    def spawn_robot(self, robot_name, urdf_path, x=0.0, y=0.0, z=0.5):
        """Spawn robot in Gazebo."""
        # Read URDF file
        with open(urdf_path, 'r') as f:
            robot_xml = f.read()

        # Create request
        request = SpawnEntity.Request()
        request.name = robot_name
        request.xml = robot_xml
        request.robot_namespace = robot_name
        request.initial_pose.position.x = x
        request.initial_pose.position.y = y
        request.initial_pose.position.z = z

        # Call service
        future = self.spawn_client.call_async(request)
        rclpy.spin_until_future_complete(self, future)

        if future.result() is not None:
            self.get_logger().info(f'Successfully spawned {robot_name}')
            return True
        else:
            self.get_logger().error(f'Failed to spawn {robot_name}')
            return False

def main():
    rclpy.init()
    spawner = RobotSpawner()

    # Spawn robot
    urdf_path = '/path/to/humanoid.urdf'
    spawner.spawn_robot('humanoid_01', urdf_path, x=0.0, y=0.0, z=0.5)

    spawner.destroy_node()
    rclpy.shutdown()

if __name__ == '__main__':
    main()

# bridge.launch.py
from launch import LaunchDescription

5.9 Debugging Gazebo Simulations​

5.9.1 Common Issues and Solutions​

1. Robot Falls Through Ground:

<!-- Ensure ground plane has collision -->
<collision name="collision">
  <geometry>
    <plane><normal>0 0 1</normal></plane>
  </geometry>
</collision>

<!-- Check robot initial pose (z > 0) -->
<pose>0 0 0.5 0 0 0</pose>

2. Robot Explodes or Becomes Unstable:

  • Cause: Physics step too large or incorrect inertia
  • Solution: Reduce step size
<physics name="1ms" type="ode">
  <max_step_size>0.001</max_step_size>  <!-- Smaller = more stable -->
</physics>

3. Sensors Not Publishing Data:

# Check Gazebo topics
gz topic -l

# Echo sensor data
gz topic -e -t /camera

# Check ROS 2 topics
ros2 topic list
ros2 topic echo /camera/image

4. Model Not Loading:

# Set Gazebo model path
export GZ_SIM_RESOURCE_PATH=/path/to/models:$GZ_SIM_RESOURCE_PATH

# Verify URDF syntax
check_urdf robot.urdf

# Validate SDF
gz sdf --check robot.sdf

5.9.2 Gazebo Diagnostic Tools​

Command-Line Tools:

# List all models in simulation
gz model -l

# Get model info
gz model -m humanoid -i

# Get model pose
gz model -m humanoid -p

# Set model pose
gz model -m humanoid -x 1 -y 2 -z 0.5

# Pause/unpause simulation
gz world -p 1  # Pause
gz world -p 0  # Unpause

# Get simulation stats
gz stats

Logging and Playback:

# Record simulation state
gz log -d ~/gazebo_logs

# Play back recorded simulation
gz log -p ~/gazebo_logs/state.log

5.10.2 Launch Configuration​

# office_simulation.launch.py
import os
from launch import LaunchDescription
from launch.actions import IncludeLaunchDescription
from launch_ros.actions import Node
from ament_index_python.packages import get_package_share_directory

def generate_launch_description():
    pkg_dir = get_package_share_directory('humanoid_simulation')

    # Gazebo with custom world
    gazebo = IncludeLaunchDescription(
        os.path.join(
            get_package_share_directory('gazebo_ros'),
            'launch', 'gazebo.launch.py'
        ),
        launch_arguments={
            'world': os.path.join(pkg_dir, 'worlds', 'office.sdf'),
            'verbose': 'true'
        }.items()
    )

    # Spawn humanoid
    spawn_humanoid = Node(
        package='gazebo_ros',
        executable='spawn_entity.py',
        arguments=[
            '-entity', 'humanoid',
            '-file', os.path.join(pkg_dir, 'urdf', 'humanoid.urdf'),
            '-x', '0', '-y', '0', '-z', '1.0'
        ]
    )

    # ROS-Gazebo bridge
    bridge = Node(
        package='ros_gz_bridge',
        executable='parameter_bridge',
        arguments=[
            '/camera/image@sensor_msgs/msg/Image@gz.msgs.Image',
            '/joint_states@sensor_msgs/msg/JointState@gz.msgs.Model'
        ]
    )

    return LaunchDescription([
        gazebo,
        spawn_humanoid,
        bridge
    ])

  • ✅ URDF structure and syntax for robot description

Key Takeaways​

  1. URDF is ROS-centric: Best for robot descriptions in ROS ecosystems
  2. SDF is more powerful: Supports multiple models, plugins, and world descriptions
  3. Conversion is seamless: Gazebo handles URDF-to-SDF automatically
  4. World design matters: Proper lighting, terrain, and physics affect robot behavior
  5. ROS-Gazebo bridge: Essential for connecting simulation to ROS 2 control
  6. Plugins extend functionality: Use plugins for sensors, actuators, and custom behaviors
  7. Debug systematically: Use Gazebo CLI tools and logging for troubleshooting
