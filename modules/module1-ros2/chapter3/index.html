Chapter 3: Humanoid Robot Description

Learning Objectives​

By the end of this chapter, you will be able to:

  1. Understand URDF (Unified Robot Description Format) structure and syntax
  2. Define links and joints for humanoid robot models
  3. Apply kinematic principles to humanoid robot design
  4. Use xacro to create modular and maintainable robot descriptions
  5. Visualize robot models in RViz
  6. Publish robot state using robot_state_publisher

3.1 Introduction to URDF​

URDF (Unified Robot Description Format) is an XML-based format for describing robots in ROS 2. It defines:

  • Robot structure: Links (rigid bodies) and joints (connections)
  • Visual properties: Appearance for visualization
  • Collision geometry: Simplified shapes for physics simulation
  • Inertial properties: Mass, center of mass, inertia tensors
  • Sensors and actuators: Cameras, LiDAR, motors
Why URDF Matters

URDF is the universal language for robot description in ROS 2. It's used by:

  • RViz: For visualization
  • Gazebo/Isaac Sim: For physics simulation
  • MoveIt 2: For motion planning
  • robot_state_publisher: For transform broadcasting

URDF vs SDF​

FeatureURDFSDF (Simulation Description Format)
PurposeRobot descriptionComplete world/scene description
ComplexitySimplerMore feature-rich
KinematicsTree structure onlySupports closed loops
UsageROS ecosystemGazebo, Ignition
ExtensibilityLimitedPlugins, custom tags

3.2 URDF Building Blocks​

Links​

A link represents a rigid body in the robot. Each link can have:

<link name="torso">
  <!-- Visual: How it appears in visualization -->
  <visual>
    <origin xyz="0 0 0" rpy="0 0 0"/>
    <geometry>
      <box size="0.3 0.2 0.4"/>
    </geometry>
    <material name="blue">
      <color rgba="0 0 0.8 1.0"/>
    </material>
  </visual>

  <!-- Collision: Simplified geometry for physics -->
  <collision>
    <origin xyz="0 0 0" rpy="0 0 0"/>
    <geometry>
      <box size="0.3 0.2 0.4"/>
    </geometry>
  </collision>

  <!-- Inertial: Physical properties -->
  <inertial>
    <origin xyz="0 0 0" rpy="0 0 0"/>
    <mass value="10.0"/>
    <inertia ixx="0.1" ixy="0.0" ixz="0.0"
             iyy="0.1" iyz="0.0" izz="0.1"/>
  </inertial>
</link>

Geometry Types:

  • <box size="x y z"/>: Rectangular box
  • <cylinder radius="r" length="l"/>: Cylinder
  • <sphere radius="r"/>: Sphere
  • <mesh filename="package://my_robot/meshes/arm.stl" scale="1 1 1"/>: 3D mesh

Joints​

A joint connects two links and defines their relative motion:

<joint name="shoulder_pitch" type="revolute">
  <!-- Parent link (fixed in joint frame) -->
  <parent link="torso"/>

  <!-- Child link (moves with joint) -->
  <child link="upper_arm"/>

  <!-- Joint origin relative to parent -->
  <origin xyz="0.0 0.15 0.2" rpy="0 0 0"/>

  <!-- Rotation/translation axis -->
  <axis xyz="0 1 0"/>

  <!-- Joint limits -->
  <limit lower="-1.57" upper="3.14"
         effort="50.0" velocity="2.0"/>

  <!-- Dynamics -->
  <dynamics damping="0.1" friction="0.05"/>
</joint>

Joint Types:

  1. fixed: No movement (e.g., torso to pelvis)
  2. revolute: Rotation with limits (e.g., elbow: 0° to 150°)
  3. continuous: Unlimited rotation (e.g., wheels)
  4. prismatic: Linear translation (e.g., elevator joints)
  5. floating: 6 DOF (rarely used, mainly for mobile bases)
  6. planar: 2D motion in a plane

3.3 Humanoid Robot Kinematics​

Coordinate Frames (REP 103)​

ROS 2 follows REP 103 coordinate convention:

  • X-axis: Forward (red)
  • Y-axis: Left (green)
  • Z-axis: Up (blue)
        Z (up)
        |
        |
        +------ X (forward)
       /
      /
     Y (left)

Joint Rotations​

  • Pitch: Rotation around Y-axis (nodding)
  • Yaw: Rotation around Z-axis (turning head)
  • Roll: Rotation around X-axis (tilting head)

Humanoid Kinematic Chain​

A typical humanoid robot has multiple kinematic chains:

                    HEAD
                      |
                  (neck joint)
                      |
    LEFT_ARM ---- TORSO ---- RIGHT_ARM
                      |
                  BASE_LINK
                   /     \
          LEFT_LEG         RIGHT_LEG

Example Kinematic Chain (Right Arm):

TORSO → right_shoulder → right_upper_arm → right_forearm → right_hand

3.5 Using Xacro for Modular URDF​

Xacro (XML Macros) extends URDF with:

  • Constants: Define values once, use everywhere
  • Math operations: Compute values dynamically
  • Macros: Reusable components (e.g., left/right arms)
  • Conditionals: Include/exclude parts based on conditions

Xacro Example: Arm Macro​

<?xml version="1.0"?>
<robot xmlns:xacro="http://www.ros.org/wiki/xacro" name="humanoid">

  <!-- Constants -->
  <xacro:property name="arm_length" value="0.30"/>
  <xacro:property name="forearm_length" value="0.24"/>
  <xacro:property name="arm_radius" value="0.04"/>

  <!-- Macro: Arm (reusable for left/right) -->
  <xacro:macro name="arm" params="prefix reflect">

    <!-- Upper Arm Link -->
    <link name="${prefix}_upper_arm">
      <visual>
        <origin xyz="0 0 ${-arm_length/2}" rpy="0 0 0"/>
        <geometry>
          <cylinder radius="${arm_radius}" length="${arm_length}"/>
        </geometry>
        <material name="gray">
          <color rgba="0.5 0.5 0.5 1.0"/>
        </material>
      </visual>
      <inertial>
        <origin xyz="0 0 ${-arm_length/2}" rpy="0 0 0"/>
        <mass value="1.5"/>
        <inertia ixx="0.012" ixy="0.0" ixz="0.0"
                 iyy="0.012" iyz="0.0" izz="0.001"/>
      </inertial>
    </link>

    <!-- Shoulder Joint -->
    <joint name="${prefix}_shoulder_pitch" type="revolute">
      <parent link="torso"/>
      <child link="${prefix}_upper_arm"/>
      <origin xyz="0 ${reflect * 0.16} 0.15" rpy="0 0 0"/>
      <axis xyz="0 1 0"/>
      <limit lower="-1.57" upper="3.14" effort="30.0" velocity="2.0"/>
    </joint>

    <!-- Forearm Link -->
    <link name="${prefix}_forearm">
      <visual>
        <origin xyz="0 0 ${-forearm_length/2}" rpy="0 0 0"/>
        <geometry>
          <cylinder radius="${arm_radius * 0.75}" length="${forearm_length}"/>
        </geometry>
        <material name="gray"/>
      </visual>
      <inertial>
        <origin xyz="0 0 ${-forearm_length/2}" rpy="0 0 0"/>
        <mass value="1.0"/>
        <inertia ixx="0.005" ixy="0.0" ixz="0.0"
                 iyy="0.005" iyz="0.0" izz="0.0005"/>
      </inertial>
    </link>

    <!-- Elbow Joint -->
    <joint name="${prefix}_elbow" type="revolute">
      <parent link="${prefix}_upper_arm"/>
      <child link="${prefix}_forearm"/>
      <origin xyz="0 0 ${-arm_length}" rpy="0 0 0"/>
      <axis xyz="0 1 0"/>
      <limit lower="0.0" upper="2.44" effort="20.0" velocity="2.0"/>
    </joint>

  </xacro:macro>

  <!-- ============ INSTANTIATE ARMS ============ -->
  <!-- Torso link (assumed to exist) -->
  <link name="torso"/>

  <!-- Right Arm: reflect = -1 (right side) -->
  <xacro:arm prefix="right" reflect="-1"/>

  <!-- Left Arm: reflect = 1 (left side) -->
  <xacro:arm prefix="left" reflect="1"/>

</robot>

Convert Xacro to URDF:

xacro humanoid.xacro > humanoid.urdf

3.6 Inertial Properties​

Accurate inertial properties are critical for realistic simulation.

Calculating Inertia Tensors​

For common shapes:

Box (mass m, dimensions x, y, z):

Ixx = (1/12) * m * (y² + z²)
Iyy = (1/12) * m * (x² + z²)
Izz = (1/12) * m * (x² + y²)

Cylinder (mass m, radius r, length l):

Ixx = Iyy = (1/12) * m * (3r² + l²)
Izz = (1/2) * m * r²

Sphere (mass m, radius r):

Ixx = Iyy = Izz = (2/5) * m * r²
Inertia Importance

Incorrect inertia values cause:

  • Unrealistic simulation behavior
  • Instability in physics engines
  • Failed sim-to-real transfer

Use CAD software or mesh analysis tools to compute accurate inertias for complex shapes.

3.7 Visualizing URDF in RViz​

Publishing Robot State​

Use robot_state_publisher to broadcast transforms:

#!/usr/bin/env python3
import rclpy
from rclpy.node import Node
from sensor_msgs.msg import JointState
from std_msgs.msg import Header

class JointStatePublisher(Node):
    def __init__(self):
        super().__init__('joint_state_publisher')

        # Publisher for joint states
        self.publisher = self.create_publisher(
            JointState,
            '/joint_states',
            10
        )

        # Timer to publish at 50 Hz
        self.timer = self.create_timer(0.02, self.publish_joint_states)

        # Joint names
        self.joint_names = [
            'neck_pitch',
            'right_shoulder_pitch',
            'right_elbow',
            'left_hip_pitch',
            'left_knee',
            'left_ankle_pitch'
        ]

        # Initial joint positions
        self.joint_positions = [0.0] * len(self.joint_names)

        self.get_logger().info('Joint State Publisher started')

    def publish_joint_states(self):
        """Publish current joint states"""
        msg = JointState()
        msg.header = Header()
        msg.header.stamp = self.get_clock().now().to_msg()

        msg.name = self.joint_names
        msg.position = self.joint_positions

        # Example: Animate elbow
        self.joint_positions[2] += 0.01  # right_elbow
        if self.joint_positions[2] > 2.0:
            self.joint_positions[2] = 0.0

        self.publisher.publish(msg)

def main():
    rclpy.init()
    node = JointStatePublisher()
    rclpy.spin(node)
    node.destroy_node()
    rclpy.shutdown()

if __name__ == '__main__':
    main()

3.8 Joint Limits and Safety​

Types of Limits​

  1. Position Limits: lower and upper bounds
  2. Velocity Limits: Maximum joint speed
  3. Effort Limits: Maximum torque/force
<limit lower="-1.57" upper="3.14"
       effort="50.0" velocity="2.0"/>

Define safety margins:

3.10 Best Practices​

1. Follow Naming Conventions​

prefix_part_type
Examples: left_shoulder_pitch, right_knee, head_camera

2. Use Consistent Units​

  • Length: meters
  • Mass: kilograms
  • Angles: radians
  • Time: seconds

3. Simplify Collision Geometry​

<!-- Visual: Detailed mesh -->
<visual>
  <geometry>
    <mesh filename="package://my_robot/meshes/arm_detailed.stl"/>
  </geometry>
</visual>

<!-- Collision: Simple cylinder -->
<collision>
  <geometry>
    <cylinder radius="0.04" length="0.30"/>
  </geometry>
</collision>

4. Validate URDF​

# Check URDF syntax
check_urdf my_robot.urdf

# Convert xacro and check
xacro my_robot.xacro | check_urdf

5. Modularize with Xacro​

Use macros for repeated structures (arms, legs, fingers).

Key Takeaways​

  2. Accurate inertias matter: Critical for realistic simulation
  3. Xacro reduces duplication: Macros for symmetric parts
